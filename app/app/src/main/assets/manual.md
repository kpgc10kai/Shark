# Shark user manual

Shark drives the device-side 98260 exploit as the shell user through Stellar or
Shizuku, then loads the manager LKM. On first use, grant access first, then run
the one-click root.

> Shark currently supports OPlus-family devices on the 6.18.21 kernel (such as
> the OnePlus 16), OPlus/Realme devices on the 6.12.69 kernel, and the
> separately ported vivo V2505A (kernel
> `6.12.23-android16-5-g41f4cb1fa7c7-abogki465038634-4k`). The V2505A entry is
> only enabled for that exact kernel build and has so far been verified on
> hardware only with KernelSU.

## Quick start

1. Install the ROOT manager you want (KernelSU / FinaSU / KernelSU Next /
   BakaSU / SukiSU Ultra). **The CI build of KernelSU Next is not supported
   yet.**
2. Start **Stellar (recommended)** or **Shizuku** over wireless debugging or
   `adb`, and grant Shark access.
3. Go back to Shark's home screen, tap "one-click root" and wait for the
   success log. For the V2505A entry, success means `DONE`, `SU_ID_RC=0` and
   `uid=0(root)`.
4. On success the manager opens automatically; with the matching switches on,
   it also suppresses the security popup and loads **SUSFS / VFS** (the VFS
   switch only appears on 6.18.21; V2505A shows SUSFS only and uses the 6.12
   `libsusfs_guard_lkm_612.so`).
5. If the log shows **MODULE NOT LOADED**, no reboot is needed - just retry the
   root.
6. The app checks for updates on every launch: Gitee Releases first, GitHub as
   fallback; when a new version appears it shows a dialog and can download and
   hand it to the system installer. You can also tap "check for updates" on the
   About page.

## Permissions and preparation

- **Stellar first, Shizuku as fallback**: if both are available Stellar is used;
  Shizuku is only used when Stellar is unavailable.
- **The manager must be installed first**: `ksud` is not bundled - at runtime it
  is executed in place from the manager APK's `lib/arm64`.
- **Run it right after a clean boot** when possible; 6.18, 6.12 and V2505A are
  three independent entries and the app picks one from the exact kernel build.

## What the one-click root does

**preflight** (kernel release / trace channel) -> **98260 UAF** (fake cred /
no SELinux writes) -> **one-shot `ksud late-load` from the cred child process**
-> wait for the module and `su` -> **cleanup** (`ksud install`, unload the
kernel guard, SUSFS, VFS, restore screenshots, launch the manager).

V2505A uses its own single-entry binary `libv2505a` (the same C plant compiled
with `-DV2505A`) and does not reuse the constants from `t98260` / `t61269`. It
also zeroes the `__tracepoint_sys_exit->funcs` slot used by `vr.ko` before
waking the root child process.

- **Fast path**: the plant takes about 2-3 seconds and the whole run about 4-9
  seconds; a reclaim miss adds a few seconds, which is normal jitter.
- **After all three chains fail**: the page held by the plant is handed to the
  holder, and the same boot can simply try again; do not kill or reap the holder
  by hand.

## Features

- **Home**: root-manager dropdown, four or five flow switches (the VFS switch is
  only shown on 6.18; V2505A shows SUSFS only), and an info card with the kernel
  version and the automatically selected exploit.
- **Log**: live streaming log for the current run.
- **History**: one `.log` per run; tap to read it, swipe left to reveal "export"
  and share it with another app.
- **About**: version, update check, links to source / community / issue
  tracker, the dependency list generated by AboutLibraries (version and license
  per library, tap for details) and the full open-source licenses bundled
  offline in the APK (GPL-3.0, NOTICE, Apache-2.0, MIT, GPL-2.0, MPL-2.0).
- **Extras -> Droidspaces support** (6.18.21 only): "download module" fetches
  the latest `Droidspaces-LKM` release from GitHub and, after confirmation,
  downloads the module zip to `Download/Shark/`; then flash it from the
  KernelSU manager under Modules -> Install. The module is not bundled in the
  APK.
- **ROOT manager -> Dynamic Switching** (6.18.21 / 6.12.69 / V2505A 6.12.23):
  run once from a clean boot; `libksud_universal.so` loads the universal KSU LKM
  (initially KernelSU, with both 6.18 and 6.12 KMI KOs embedded). After that,
  "manager hot-switch" appears under Extras, where you can switch between
  KernelSU / KernelSU-Next / BakaSU / SukiSU / FinaSU without a reboot or a
  re-exploit; reopen the target manager app after switching.

## Troubleshooting

| Log | What to do |
| --- | --- |
| `PROBE_FAIL` / `kernel mismatch` | The current kernel is not in the supported list (6.18.21, 6.12.69, or the exact V2505A kernel). |
| `MANAGER` / `KSUD_MISSING` | Install the matching manager APK first, then run again. |
| `STALE_PLANT` | The previous plant is still running; wait for it to become the holder and retry. |
| `PLANT_FAIL` | The plant keeps the holder and exits; retry on the same boot. |
| `LATE_LOAD_FAIL` | The module did not appear in time; check the ksud output in the log, make sure the manager version matches, then retry. |
| Kernel panic / reboot | Inherent race risk of 98260; run it again after the reboot. |

## How it runs

- **6.18.21** -> CVE-2026-98260-6.18 (`libt98260.so`); **6.12.69** ->
  CVE-2026-98260-6.12 (`libt61269.so`).
- **Exact V2505A kernel** -> CVE-2026-98260-vivo-V2505A (`libv2505a.so`); this
  is the third independent single-entry binary, with extra handling for vivo's
  `vr.ko`, and it does not reuse the other two.
- All three entries run in place as app native libraries (`nativeLibraryDir`)
  and never deploy tools to `/data/local/tmp`; `ksud` is likewise executed in
  place from the installed manager APK. SUSFS is supported by all three entries
  (6.12/V2505A use `libsusfs_guard_lkm_612.so`); the VFS switch is only exposed
  for the 6.18 entry.
- For system research on your own devices only.
